## Likely technical seams (review findings, not proven root causes)

- `backend/collectors/screen_ocr.py` / `backend/collectors/league_window.py`: focused-only client ROI, `SCAN_STAGES`, guarded 3-title crop, temporal OCR. Capture is prohibited when League is not confirmed as foreground.
- `frontend/app.js` `updateOcrStatusBadge`, `setOcrFocusStale`, `handleMessage`, `autoExpandSections`, `bindOcrControls`: a stale/unavailable status is labelled `NOT FOCUSED` and manual scan button disabled; when `offerState !== present`, build panel auto-expands even if an actual offer is visible but OCR cannot recognize it.
- `backend/static_data/loader.py` `_load_items`: generic Data Dragon `purchasable` + map 11/12 filtering has no verified per-mode/per-augment quest gate.
- `backend/engine/build_suggester.py` `suggest_build`: recomputes every pipeline tick but ranks all loaded items in all four style lists, does not validate true item availability. `frontend/app.js` renders `Other paths` regardless of user preference to see only one.
- `frontend/index.html` and `frontend/style.css`: duplicated `AUGMENT PICK` and `DETECT AUGMENTS` sections and permanent top-right header overlay.
- `backend/workflow/pipeline.py` already passes observed `active_augments`, `purchased_items`, enemy and ally profiles into the build scorer. Preserve these inputs; correctness requires safe eligibility and better conditional presentation, not another disconnected recommendation engine.
